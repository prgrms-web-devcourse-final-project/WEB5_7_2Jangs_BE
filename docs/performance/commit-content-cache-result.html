Redis 장애 gate

통과. Redis stop 뒤 health는 UP/HTTP 200, verify exit 0, checks 95/95, HTTP failure 0%였다. get/put error는 각각 0→6, 0→3으로 증가해 장애를 관측하면서 DB fallback 응답 성공을 확인했다. restart 뒤 miss 82→88, put success 41→44, 이어 hit 1,590→1,593으로 재채움과 hit 회복을 확인했다.

이 안전성 증거는 Redis를 배제하지 않지만, Redis가 Caffeine보다 최소 의미 차이 이상 우수하다는 성능 증거도 아니다.

다음 단계와 한계

  • 새 cold evidence는 Caffeine 후보 결론을 약화하지만 core 6개 선택 규칙을 반전하지는 않는다.
  • 선택된 Caffeine만 남기는 adoption design을 작성하고, cold miss/single-flight와 초기 채움 경로를 별도 검증한다.
  • staging은 그 설계 뒤 Mixed/VU50/60초 3회 방향성 확인만 검토하며 saturation은 실행하지 않는다.
  • 구현 hash는 61b171f0d8e888c04daeb92021aba58bdb911f62지만, 측정 당시 working tree가 미커밋이라 hash만으로 구현을 재현할 수 없다.
  • 실제 운영 로그·트래픽 기반 증거는 없으며, 로컬 절대 수치와 운영 절대 수치를 합치지 않는다.
