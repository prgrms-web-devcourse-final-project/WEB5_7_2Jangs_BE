Perf 디렉터리 재구성 계획

성능 측정 주제를 results 아래가 아니라 perf 계층에서 먼저 분리합니다. 기존 결과는 삭제하지 않고 이동하며, raw 결과는 계속 Git에서 제외합니다.

목표 구조

perf/
├── seed/
├── read/
│   ├── commit-cache/results/
│   ├── cqrs/results/
│   ├── graph/results/
│   └── simple-read-probes/results/
├── delete/
│   ├── bulk/results/
│   └── single/results/
└── thumbnail/
    ├── preview-e2e/results/
    └── workflow/results/

정리 원칙

  • 도메인 → 시나리오 → 실행 파일과 results 순서로 배치
  • 공용 seed는 perf/seed 유지
  • 사람용 결론 문서는 docs/performance 유지
  • raw 결과는 Git 제외, 검증용 요약만 results/evidence 추적
  • single_delete는 delete/single로 통합

검증

경로 참조를 갱신한 뒤 Node/Bash 테스트, 이전 경로 검색, diff 공백 검사를 수행합니다.

커밋과 push는 이 작업에서 수행하지 않습니다.
