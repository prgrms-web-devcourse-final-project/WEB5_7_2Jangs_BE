Docsa 모니터링 통합

운영과 스테이징에서 중복 실행하던 관측 스택을 하나로 통합하고, 스테이징 모니터링 데이터 볼륨을 안전하게 정리하는 계획이다.

구현 방향

운영 Compose가 Prometheus·Grafana·Loki·Promtail·cAdvisor·Node Exporter를 소유한다. 운영 Prometheus는 공유 네트워크로 스테이징 앱과 MySQL Exporter를 함께 수집한다.

작업 순서

  1. 공유 네트워크, target, 로그 필터, 보존 기간을 계약 테스트로 고정한다.
  2. 운영·스테이징 MySQL slow log 경로를 분리한다.
  3. 서버에서 target과 외부 서비스를 검증한 뒤 스테이징 중복 모니터링 컨테이너와 데이터 볼륨을 제거한다.

보호 대상

stg_mysql_data와 mailpit_data는 삭제하지 않는다. 애플리케이션은 모니터링 장애에 의존하지 않아야 한다.

위험과 검증

스테이징 모니터링 볼륨 삭제는 target 검증 뒤에만 수행한다. 운영·스테이징 target UP, Grafana redirect, Compose 렌더링과 계약 테스트를 모두 확인한다.

세부 파일과 서버 전환 단계는 Markdown 구현 계획에서 확인한다.
