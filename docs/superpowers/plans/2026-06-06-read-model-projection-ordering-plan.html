Read Model Projection 순서 안정화

Outbox wakeup의 의미를 낮추고, 문서 목록 Read Model이 중복·역순 이벤트를 안전하게 처리하도록 만드는 구현 계획이다.

해결하려는 문제

특정 outbox row를 즉시 처리하는 wakeup과 단일 projection marker의 조합은 같은 문서 이벤트가 역순으로 반영될 때 일부 필드를 누락시키거나 삭제된 문서를 되살릴 수 있다.

구현 순서

  1. wakeup이 relay 실행 신호로 동작하는지 실패 테스트를 먼저 작성한다.
  2. relay가 OPEN 이벤트를 생성 순서대로 처리하도록 바꾼다.
  3. 필드별 projection marker와 삭제 terminal guard의 실패 테스트를 작성한다.
  4. title·activity·thumbnail·삭제 이벤트 규칙을 구현한다.
  5. 기존 테스트와 백필 경계를 정리하고 전체 테스트를 실행한다.

영향과 검증

문서 목록 API와 DB 스키마 계약은 바꾸지 않는다. 단위 테스트로 필드별 역순·중복·삭제 이후 이벤트를, 통합 테스트로 relay의 생성 순서 처리를 검증한다.

남는 한계

여러 서버가 relay를 동시에 실행하는 완전한 aggregate 단위 순서 보장은 제공하지 않는다. 그 단계에서는 aggregate version 또는 consumer checkpoint를 별도 설계한다.
