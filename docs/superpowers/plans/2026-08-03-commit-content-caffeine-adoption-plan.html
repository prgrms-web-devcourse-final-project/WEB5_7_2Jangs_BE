커밋 내용 Caffeine 최종 채택

비교 실험용 none/Caffeine/Redis 경계를 단일 인스턴스 운영에 맞는 Caffeine과 Spring Cache로 단순화한다.

결정

운영 경로는 @Cacheable(sync = true)와 @CacheEvict를 사용하는 Caffeine 하나로 유지한다. none은 성능 기준선과 즉시 비활성화 설정으로만 남긴다.

구현 범위

  1. Caffeine cache manager와 enabled=false의 NoOp 경로를 검증한다.
  2. 동일 키 single-flight, eviction, 서로 다른 키 독립성을 테스트한다.
  3. 조립 시간은 cache proxy 밖이 아닌 assembler 경계에서 관측한다.
  4. Redis 운영 의존성과 Compose·통합 테스트를 제거하고 회귀를 확인한다.

운영 제약

TTL은 접근 후 10분, 최대 크기는 400개다. staging 부하와 saturation 재측정은 실행하지 않으며, 대표 성능 검증은 Hot·Mixed·Cold VU50에서 none/Caffeine 각 3회로 제한한다.

한계

과거 Redis 비교 결과는 보존하되 최종 어노테이션 구현의 성능으로 일반화하지 않는다. Cold miss 경로는 별도 재측정과 관찰이 필요하다.
